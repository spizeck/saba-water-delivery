# GitHub Wiki draft source

These are staging/source files for a future human-facing GitHub Wiki for Public Entity Saba staff and maintainers, prepared for [issue #64](https://github.com/spizeck/saba-water-delivery/issues/64). Start at [Home](Home.md). They are reviewable repository material, not a published Wiki or government acceptance record.

Retain this directory intentionally as the reviewed Wiki source after eventual publication. Future edits should be reviewed here and then synchronized to the Wiki. Publication is a separate action; this change does not publish anything to the Wiki.

## Authority and linking

Repository documentation remains authoritative for implementation details, exact technical procedures, ADRs, deployment, testing, and disaster recovery. These pages explain operator decisions and route readers to those sources. Short explanations of statuses and responsibilities are repeated for comprehension; command runbooks, configuration tables, schema definitions, and ADR rationale are not copied.

Canonical documentation links use full GitHub `blob/main` URLs so they continue pointing to the application repository when pages move to the separate Wiki repository. Sibling `.md` links make the draft navigable in the repository. At publication, adapt sibling links to GitHub Wiki page URLs and verify navigation; do not blindly copy repository-relative links into a different repository. Recheck status claims against issues and source before publishing.

The repository link checker examines tracked Markdown, so stage new pages before running it. It does not exclude `wiki-draft/`, but deliberately skips external URLs. Validate the repository file paths behind canonical GitHub URLs separately; a local path check is not a remote availability test.

## Additional conflict: automatic-offer candidate window (Aikido review)

- **Conflicting claims:** this draft's Dispatcher Guide and System Concepts,
  canonical Dispatcher Guide, DATA_MODEL, CHANGELOG, PRODUCT priority summary,
  and ADR 0007 could imply complete-queue escalation ordering. TECHNICAL's
  selection descriptions omitted candidate truncation.
- **Implementation evidence:** at main `dccae8aae9aa9d7dbaa1a61e30fe952a225c8522`
  and PR head `468268dfb40e5136a21f5ba78d30448ecb5963d6`,
  [dispatch.ts](https://github.com/spizeck/saba-water-delivery/blob/main/src/lib/domain/dispatch.ts)
  queries available requests by `priorityRank`, then `requestedAt`, with
  `limit(100)` before mapping and sorting.
  [dispatchQueueCompare](https://github.com/spizeck/saba-water-delivery/blob/main/src/lib/domain/dispatchBatchSelection.ts)
  applies override rank only within those results. The
  [selector](https://github.com/spizeck/saba-water-delivery/blob/main/src/lib/domain/dispatchSelection.ts)
  reuses valid pending offers, prioritizes a separately fetched hold
  (query limit 1), and filters declines without fetching another page.
  The escalation action sets rank 0 and releases a held request to available.
- **Verification:** a synthetic, read-only experiment using the actual comparator
  and selector with the observed query order/limit modeled in memory produced
  request 1 from a 100-result window of 101 same-priority requests, whereas the
  complete comparator selected escalated request 101. No production records or
  configuration were accessed or changed; this was not a Firestore emulator test.
- **Conclusion:** Aikido is correct. Comparator policy and candidate completeness
  are different. Escalation can be recorded yet fail to surface newer work.
  Delivery Run selection has no corresponding 100-result limit; do not infer
  automatic-offer coverage from that list. No existing runtime issue covered
  this after searching all open and closed repository issues.
- **Follow-up:** [#66](https://github.com/spizeck/saba-water-delivery/issues/66)
  documents the 101-request reproduction, impact, invariant, query/index/legacy
  data concerns, concurrency requirements, and query-level regression coverage.
- **Documentation changed:** PRODUCT.md, TECHNICAL.md, docs/DISPATCHER_GUIDE.md,
  docs/DATA_MODEL.md, docs/CHANGELOG.md, and the draft Dispatcher Guide, System
  Concepts, Known Limitations and Roadmap, and this README. ADR 0007 receives a
  dated implementation qualification preserving its original policy. The entire
  repository Markdown set was searched for rank, escalation, fairness, and queue
  ordering claims; unrelated incident-escalation wording is unchanged.

This follow-up changes documentation only. It does not fix the runtime query or
claim that production has experienced a particular backlog or delayed delivery.
