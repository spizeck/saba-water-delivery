# NNNN. Short decision title

- **Status:** Proposed | Accepted | Superseded by ADR-XXXX
- **Date:** ADR recorded YYYY-MM-DD (decision originally made YYYY-MM-DD, or
  "records an earlier existing decision; original date approximate")

## Context

What situation, constraint, or forces led to this decision? Keep it factual and
grounded in the repository — do not invent decisions the code does not support.

## Decision

The decision, stated plainly. What the system does and the boundary it sets.

## Alternatives considered

The main options that were weighed and why they were not chosen. Be honest about
trade-offs; "none seriously considered" is a valid entry if true.

## Consequences

What this decision makes easy, hard, or impossible. Include the downsides.

## Operational implications

What a maintainer or government IT administrator must know to operate, recover,
or safely change this. Call out any assumption that must not be accidentally
undone.

## References

Links to the implementation docs, source files, Firestore rules, workflows,
issues, or PRs that are the authoritative current mechanics. Do not list every
file — just the ones that matter.
